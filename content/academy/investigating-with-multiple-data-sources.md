## Understand the concept

An investigation correlates observations from endpoint, network, identity and application sources. Preserve original records and document transformations. Distinguish event time from collection time, and record timezone assumptions. A hash supports integrity checking but does not establish how the evidence was originally collected.

## Apply it to a realistic decision

A process name alone does not establish legitimacy. Correlate its path, parent, signature, command line and associated network activity. Missing data limits conclusions: absence from one logging source does not prove an event never occurred. Report gaps alongside findings.

## Practice and explain

Build a timeline from the synthetic Windows events and incident log. Include the evidence filename and line or record identifier for each statement.

Write a short answer before checking the flashcard or quiz. Include the evidence you would collect, a likely failure case, and a limitation of your proposed control. Good security work makes assumptions visible and gives another person a way to verify the result.

## Check your understanding

What does evidence provenance record?

**Expected reasoning:** Where evidence came from, how it was collected, and how it has been handled. Timezone conversion and clock skew can create apparent ordering errors.
