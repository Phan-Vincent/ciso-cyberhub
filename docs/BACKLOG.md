# Prioritized backlog

## P0 — before public club launch

1. Obtain club approval, organization ownership, two maintainers and an approved release URL. Acceptance: documented owner, protected main, release permissions and successful rollback rehearsal.
2. Run Chromium/browser smoke tests, real mobile checks and keyboard/screen-reader review. Acceptance: all interactions work at root and repository base paths; no uncaught errors, blocked assets or horizontal overflow.
3. Reconcile current Security+ provider version and official objective document. Acceptance: active/retirement state verified, source date recorded and mapped edition clearly identified. Keep the course introductory until independent review and deep coverage exist.
4. Run live KEV, EPSS, NVD and feed acceptance. Acceptance: valid records, source timestamps, documented feed permission/terms, outage recovery and no fixture contamination.
5. Execute all tutorials and labs on documented versions. Acceptance: setup, commands, expected output and troubleshooting independently reproduced.
6. Validate GitHub workflow actions and PR automation in the actual organization. Acceptance: only allowlisted JSON changes, no branch code execution, no unexpected writes, human merge and authorized deployment.

## P1 — meet the fuller content scope

7. Expand to 100–150 useful tool records based on primary evidence. Resolve current versions, license scope, installation URLs and supported OS values. Reject non-open-source candidates or label them clearly outside the open-source collection.
8. Deepen each Security+ subobjective with original explanations, scenarios and multiple independent questions. Add a coverage matrix at subtopic granularity, balanced mock exams and performance tasks. Obtain subject-matter review before a completion label.
9. Add verified introductory pathways for Network+, ISC2 CC and SOC tracks, then offensive/cloud/governance courses. Check names and eligibility from providers; do not reuse stale exam codes.
10. Add source-backed summaries only where source access and editorial review support them. Broaden permitted feeds and implement explicit summary review states.
11. Adopt an approved-data publication policy so routine factual source refresh can be deployed automatically without promoting unverified editorial claims. Keep tool/curriculum approvals separate.

## P2 — scale and usability

12. Migrate to Astro/Starlight when package access is available if its ecosystem benefit outweighs migration cost. Preserve URLs, content, progress namespaces and acceptance tests; avoid dual implementations.
13. Add semantic TypeScript checking, a maintained Markdown parser and a stronger lint configuration with a reviewed lockfile and dependency audit.
14. Paginate/shard the directory at measured browser limits and shard historical news by year. Preserve source provenance and establish an explicit archive-retention policy.
15. Improve EPSS coverage in bounded batches and NVD caching/rotation based on freshness. Add explicit enrichment-status UI and corrected-record history.
16. Add optional offline lab containers with reviewed image digests, resource limits and no exposed default ports. Keep the main site useful without them.
17. Add a real-browser accessibility CI job and independent automated scanning once a reviewed test dependency can be installed and locked.
